# FirstSeen services and credentials

Never paste credentials into chat. Locally, values belong in ignored mode-600 `.env.local` or the
approved mode-600 consolidated file outside the repository. In production, use Vercel encrypted
environment variables and provider-managed secret settings. Supabase server/database credentials,
OpenAI/search keys, Inngest signing material, Slack webhook, salts, and deploy tokens are never
browser variables.

## Explicitly unnecessary

- No Gmail/email, Google OAuth, referral outreach, applicant-tracking, or auto-apply credentials.
- No LinkedIn, Indeed, Simplify, browser-session, CAPTCHA, proxy, or scraping credentials. Simplify
  remains a user-controlled browser autofill extension after FirstSeen opens the official Apply URL.
- No geocoding/distance API: accepted areas use a reviewed candidate-specific place policy and
  uncertain locations route to Review. A paid distance provider is not justified for one user.
- No separate queue/Redis/rate-limit provider: Inngest is the durable workflow service and
  PostgreSQL stores atomic throttles/idempotency/cost state.
- No general hosting scheduler: Inngest crons continue while the laptop is offline.
- No broad Brave replacement/Tavily key; one primary search provider plus Adzuna is sufficient.

## Rotation verification

For a replacement credential: update the ignored/encrypted location without logging the value,
restart or redeploy, run only its labelled smoke/health flow, inspect safe status and persisted
usage, then revoke the old credential. Secret scanners run before publication. A complete value
must never appear in command output, CI logs, fixtures, screenshots, docs, or browser code.
